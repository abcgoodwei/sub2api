# Codex 采票凭证停用与账号出口绑定

对应 #19、#25。无需数据库迁移，票据字段继续存放在服务端管理的 account.extra 中，节点占用关系存放在托管 Mihomo 的 `settings.json`（0600）。

## 凭证失效

自动、手动采票遇到上游 HTTP 401，或 OAuth 刷新在竞争恢复后仍明确返回 `invalid_grant`、`refresh_token_invalidated` 等凭证失效错误，会持久化账号 `status=error`、`schedulable=false` 并更新调度快照。后续自动轮次跳过该账号，手动任务立即结束。重新授权后由现有账号恢复流程处理。

停用使用条件更新，只有数据库中的凭证仍匹配失败请求时才生效，避免迟到的 401 覆盖管理员刚更新的凭证。错误说明不保存上游响应或 Token。网络超时、普通探测解析失败、403、407、429、5xx、OAuth 客户端配置错误不属于此停用条件。

## 每个账号独立出口

使用内置托管 Mihomo 打票入口 `http://127.0.0.1:3101` 时：

1. 采票前选择允许使用的具体节点，通过该节点测量出口 IP。已有其他账号占用的节点或 IP 不再分配；无法测出 IP、无独立出口时，本轮不向模型发送探针。
2. 占用关系先落盘，再发送探针。成功票据记录节点配置指纹；同一账号的其他模型复用这个出口，不再各自轮换。不同账号分配不同的已测 IP。
3. 票据有效期间不提前换节点补备用票。HTTP、HTTP/SSE 透传、WS 连接池和 WS 透传使用成功采票时的出口；该账号其他模型的业务请求也沿用它，但不会注入其他模型的票据。
4. 每条票据都绑定实际节点；指纹覆盖完整节点配置。节点删除、配置替换、禁用或被地区规则排除后，旧票不得自动换出口或回退直连。收到降级票据反馈后释放对应绑定，下次重新采票。
5. 绑定以该账号各模型票据的最晚有效期为限。失效后重新分配，重启读取原绑定。开启“节点用后移出”时，成功节点仍可承载绑定账号业务，但不再给其他账号采票；用后节点仍需管理员恢复。

固定业务入口为只监听本机的 `127.0.0.1:3102`，使用按节点派生的认证和独立路由规则；不会跟随 `CODEX-ROTATE` 的共享选择器改变。需要让此端口保持可用，不需要向公网发布。面板节点列表显示绑定账号 ID、已测出口 IP、绑定有效期，不显示认证信息。原始票据与节点指纹沿用私有 extra 脱敏规则。

升级前的票据没有可证明的出口绑定。在托管模式下需要重新采票，不能猜测原出口。外部自定义打票代理继续保持原行为：应用无法固定第三方代理服务内部的轮换节点；本功能的独立出口分配仅支持托管 Mihomo。

出口 IP 是分配时的测量结果。若代理供应商让同一节点的公网出口动态变化，固定节点并不能保证公网 IP 永久不变，也不能保证上游不会降级。应使用出口稳定的节点。

## 验证方式

新增测试覆盖 401 持久化停用、手动终止、临时错误保留、条件更新保护重新授权、账号/IP 排他分配、重启恢复、节点/地区失效、HTTP/WS 绑定和凭据脱敏。

`MIHOMO_INSTALL_SMOKE=1 go test ./internal/mihomo -run TestPinnedAccountRoutesWithOfficialKernel -count=1` 下载仓库锁定的官方内核，通过本地模拟代理验证真实认证与路由，不使用真实订阅或模型请求。

Mihomo 配置依据官方 [Mixed listener](https://wiki.metacubex.one/en/config/inbound/listeners/mixed/) 与 [路由规则](https://wiki.metacubex.one/en/config/rules/) 文档；实际兼容性由上述内核测试验证。
